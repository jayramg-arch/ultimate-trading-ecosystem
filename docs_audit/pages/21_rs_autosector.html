01Your markdown guide describes a version that no longer exists

Three things changed after that guide was written

The file on disk is Mansfield_RS_AutoSector_v1.5.pine and its in-file title is v1.6. If you are working from the old guide you will look for a stage background that was deliberately deleted, and trust an input that no longer drives anything.

What the old guide saysWhat the script does now
Stage × RS background, five colours, purple for weak leadership RS-sign only — green above zero, red below
Label reads Stage · RRG · Sector Label reads RRG · Sector. No stage token
Four MA-length inputs, one per timeframe One 26-week horizon plus a smoothing switch
Rotation length 12 drives the calculation Decoupled 25 / 10 / 7 with an affine calibration — the 12 is inert
No volatility readout A momentum and volatility cell in the corner

Why the stage read was removed rather than fixed

The pane used a lightweight stage approximation — price against the 30-week average, plus a four-week slope. The canonical stage engine uses a slope threshold, a transition machine and strict-trend overrides. On a name whose 30-week average was barely positive, this pane said Stage 2 while the dashboard and the Golden Matcher said Stage 1.

The right call, and worth generalising

A second definition of a shared concept is worse than no definition. Stage lives authoritatively on the dashboard and the unified strategy; this pane stopped computing it rather than maintaining a copy that could drift again. When two surfaces disagree about a number, the answer is usually to delete one of them, not to reconcile both.

02What it does

For whatever symbol is on the chart it does four things, in its own pane below price:

  1. Detects the sector. No manual input — the mapping is the same one the dashboard uses.
  2. Plots two relative-strength curves — one against the broad index, one against that sector.
  3. Tints the pane by the sign of the index curve.
  4. Prints a one-line brief on the last bar: rotation quadrant, sector, and how the sector was resolved.

It answers one question the price chart cannot: is this name leading, and leading against whom? A stock can beat the index purely because its whole sector is hot. Two lines separate those cases in a glance; one line cannot.

Setup, once

Paste, save, add to chart — it opens in its own pane, not as an overlay. Leave the manual override off; auto-detection is the entire point of the fork. Stack it directly under the dashboard so the panes line up bar for bar.

If a ticker resolves to the wrong sector, the mapping table inside the file is generated from the sector database. Re-export it after you edit that database — the table does not read the database at runtime, it is baked in at export time.

03Sector detection — three tiers, first hit wins

#TierHow it resolves
1Database lookupA generated table covering the full broad-index universe, matched on the cleaned ticker. Highest accuracy
2Keyword fallbackFor off-list names, maps the platform's own sector and industry metadata onto an index
3DefaultThe broad index itself, when neither resolves

The label tags which tier answered — database, keyword, or manual. That tag is not decoration: a keyword resolution is a guess from platform metadata, and it is worth a second look before you rank a name on its sector line.

The self-comparison case

When a symbol resolves to the index itself, the sector line is suppressed rather than plotted flat at zero, and the label says so. Relative strength against yourself is not a reading — showing it as a flat line would look like an answer.

04The two lines

The formula is the classic one, unchanged from the community original:

ratio    = close / benchmark close
strength = (ratio / average of that ratio − 1) × 100

So the plotted value is not the ratio itself — it is how far the ratio sits from its own recent norm, as a percentage. Two consequences worth holding onto:

  • Above zero means outperforming relative to its own habit, not outperforming in absolute terms. A chronic leader that pauses can print negative while still beating the index over the year.
  • Zero is a moving reference. The average travels with price, so a line that flattens just above zero is holding a lead it already established, not building a new one.

Benchmark closes are pulled with look-ahead disabled, so the historical curve does not repaint.

Blue and orange

Blue is against the broad index. Orange is against the detected sector. The zero line is dotted, and the index curve carries a fill that lightens above zero — so the pane reads correctly at a glance even before you focus on it.

05Stair-step or smooth — the one input that changes the shape

The classic Mansfield horizon is 26 weeks. On a weekly chart that is simply a 26-bar average. On a daily or intraday chart there are two honest ways to render it, and the script gives you both:

ModeWhat it computesWhat you see
Smoothing on (default) The 26-week horizon converted into rolling bars of the chart's own timeframe — roughly 130 daily bars, or 650 bars on a 75-minute chart A continuous curve. Moves every bar
Smoothing off The true weekly value, pulled down onto the chart A staircase. One step per week, flat in between

Neither is wrong. The staircase is the literal weekly reading and never moves intra-week; the smooth curve is the same horizon expressed continuously, so it turns earlier and reads better when you are working an intraday chart. Weekly charts always use the smooth path, because on a weekly chart there is no difference to make.

If you are comparing this pane against a weekly-anchored number elsewhere and they disagree slightly mid-week, this switch is the first thing to check.

06The rotation quadrant

The label's quadrant is not derived from the plotted lines. It is the same rotation calculation the dashboard, the board, the risk allocator and the studio all run — computed on the weekly spread of the stock against the index.

RatioMomentumQuadrant
≥ 0≥ 0Leading
≥ 0< 0Weakening
< 0≥ 0Improving
< 0< 0Lagging
The calibration, and the input that no longer does anything

The rotation axes were re-fitted so that every surface in the system plots a stock in the same place. Two properties matter:

  • The axes are decoupled. The ratio and the momentum leg use different lengths — twenty-five and ten for the ratio, seven for momentum — rather than one shared length.
  • The mapping preserves the origin. The spread is scaled around the centre point, so the neutral reading stays neutral. An earlier free-fit displaced that centre, which quietly moved every name across quadrant boundaries.

Because the axes are decoupled, the rotation length input is inert for the quadrant. Its tooltip still describes the old shared-length behaviour. Changing it will not move the label — it only affects the warm-up bar count. Do not tune it expecting a different quadrant.

There is a warm-up before the quadrant resolves at all. On a freshly listed name the label will simply omit it rather than print a guess.

This is the parity claim

Because the calculation is shared rather than copied, this label always matches the rotation cell on the dashboard for the same bar. If it ever diverges, that is a bug — not a difference of opinion between two tools.

A small two-row cell, added so a momentum and volatility check does not cost two more indicators on the screen:

RowShowsColour

The volatility figure is the useful one. It is the same quantity the sizing rules divide by, so it tells you before you open the allocator roughly how large a position this name can carry at your risk budget — and whether a stop placed a couple of ranges away is a sensible distance or an absurd one.

08Where it sits in the funnel

Its job is leadership confirmation, not signal generation. Per the standing rule to lead with stage and strength, the sequence is:

  1. Stage — from the dashboard, not from here. Only an advance is buyable.
  2. Strength against the market — the blue line and the quadrant.
  3. Strength within the group — the orange line.

A name that clears all three — advancing, leading the market, leading its peers — is the textbook leader. This pane collapses steps two and three into one look.

It cannot complete the check by itself any more

Because the stage read was removed, step one now has to come from another surface. That is the cost of the v1.5 decision and it was accepted deliberately. Run this pane stacked under the dashboard rather than alone.

09Reading the two lines together

PatternWhat it meansWhat to do
Both above zero, both risingThe clean leader — beating the market and its own groupThe strongest state. Proceed to location and trigger
Blue up, orange flat or downBeating the market but only average inside a hot sector — the group is doing the workCompare peers. There is probably a stronger name in the same group
Orange up, blue flat or downLeading a group that is itself laggingSize down, or wait for the group to turn. Check the sector's own stage
Both below zeroA laggard on both countsNothing to confirm here
The most useful of the four

The second row is the one people miss. A rising blue line is not proof of stock selection — in a sector run it can be entirely borrowed. The orange line is what tells you whether you picked the right name or merely the right theme.

10The playbook

Read the quadrant against the strength sign. The stage column now comes from the dashboard sitting above this pane.

TintQuadrantRead, and action
GreenLeadingTop grade. Outperforming with momentum behind it — proceed to the entry checklist
GreenWeakeningStill ahead, but momentum is rolling over. Manage existing longs tighter; be far pickier on adds
RedImprovingThe early-turn watch. Behind, but rotating up. Alert it, do not chase it
RedLaggingNothing here. Leave it alone
GreenLaggingThe contradiction worth looking at — outperforming its own norm while the longer rotation is still behind. Often a genuine turn in progress, occasionally a dead-cat bounce. Confirm with structure before acting

The state the old guide called purple

The most valuable single reading used to be advancing but not leading — a trend intact while relative strength sat negative. That is the trend that fails first in a correction. The pane no longer paints it as one colour, because it no longer knows the stage — but the reading still exists, and it is worth assembling by hand on a held position:

  • Stage 2 on the dashboard,
  • red tint here, or a lagging quadrant.

When both are true: tighten the stop, stop adding, and rank the position against greener alternatives in the rotation matrix. A trend that is not leading is borrowed time.

Which chart to read it on

TimeframeWhat you get
WeeklyThe canonical horizon, unsmoothed by definition. The cleanest read for positional decisions
DailyThe same horizon rolled continuously. Day-to-day tracking
IntradayThe curves still resolve, but the rotation quadrant stays weekly-anchored and will not move during your session

The quadrant being timeframe-independent is a feature — flipping the chart to time an entry never changes your context read.

12Parity discipline

This pane exists to agree with other surfaces. Three checks keep it honest:

  1. The quadrant must equal the dashboard's rotation cell on the same bar. A divergence is a bug or a mismatched index input — never a tuning preference.
  2. Keep the index benchmark identical across the system. Changing it here silently forks the rotation read.
  3. Re-export the sector table after any change to the sector database, or this pane and the dashboard will disagree about which group a name belongs to.
  4. Regenerate both Pine sector maps, not just this one. The database feeds two independently generated artefacts — the lookup block in this pane, and the packed map inside the shared library that the entry trigger reads. They are produced by different commands, so re-running one leaves the other on yesterday's mapping.
The stage lesson, stated once

The reason this section exists at all is that v1.4 broke rule one on a different field. A duplicated calculation does not stay identical; a shared one cannot diverge. Where a read cannot be shared, it is better deleted here than maintained twice.

One database, two artefacts, and a publish step in between

sectors.db is the single source of truth — 684 mappings in stock_sector, and the only file worth hand-editing. Everything downstream of it is generated and should never be edited in place.

ArtefactRegenerated byReaches a chart when
This pane's lookup blocksector_manager.py export-pine <file>you recompile this script
The shared library's packed mapgen_sector_map.pyyou recompile and publish a new library version

The publish is the step that gets forgotten. A library compiles cleanly against your local edit while every script importing it still pins the old published version — so the change looks applied on the library's own tab and has not moved anywhere else. The symptom is a sector label that is right in this pane and stale on the entry trigger.

The two artefacts can also differ legitimately: the packed map dedupes on a precedence rule — a hand-set mapping beats an index membership, which beats a curated one, which beats an inferred one — and prints each collision it resolves. Read that output. A symbol that appears there is one where the database itself holds two answers, and the fix belongs in the database, not in either generated file.

13What it deliberately will not do

It does notWhy
Compute stageRemoved in v1.5 after drifting from the canonical engine. Read it on the dashboard
Infer stage from strength levelsThat would be a second stage definition — the exact failure that got the first one deleted
Paint the rotation quadrantTried, correct, and visually misleading. It lives in the label
Produce entries, stops or targetsThose belong to the screeners, the entry trigger and the allocator
Read the sector database liveThe mapping is baked in at export. Editing the database changes nothing until you re-export

What it is, stated plainly: a leadership lens with the benchmark chosen for you. It confirms; it never selects.
