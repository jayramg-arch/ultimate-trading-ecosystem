01Which version you are actually running

The markdown guide documents v6.2. The file on disk is named v6.3 and its in-file title is v6.4. Two rounds of changes landed after that guide was written, and one of them fixed a genuine silent bug.

v6.3 · the bootstrap asymmetry

The high side handled the very first pivot on a chart; the low side did not. So on any chart that opened in a downtrend, the first swing low was silently dropped — not locked, not labelled — until a high formed to boot the engine.

The fix seeds state from a first-pivot low as well, mirroring the high side exactly. It is behaviour-neutral everywhere except that early-history low. Note what kind of bug this was: nothing errored, nothing looked wrong, and it only ever affected the left edge of the chart — which is precisely why it survived so long.

v6.4 · why exporting beat re-deriving

The higher-timeframe trend states were computed for the panel and readable nowhere. So the entry-trigger script answered “what is the weekly trend?” with its own proxy — and the two panels disagreed on the same chart: this one said sideways, that one said weekly up.

Exporting the value the other script needs is strictly better than the other script re-deriving it. One structure engine on the chart, and nothing left to drift. That is the same principle that later collapsed three duplicate stage reads into one.

02What it does

It connects confirmed swing highs and lows, and classifies each new pivot against the previous pivot of the same type. The output is an objective structural map built from price alone — no lagging average anywhere in it.

ClassMeaningEffect on trend
Higher highAbove the previous swing highBullish — confirms an uptrend when paired with a higher low
Higher lowAbove the previous swing lowBullish, same pairing
Lower highBelow the previous swing highBearish, paired with a lower low
Lower lowBelow the previous swing lowBearish, same pairing
Equal highWithin a threshold of the previous highSideways — the uptrend is NOT confirmed
Equal lowWithin a threshold of the previous lowSideways — the downtrend is NOT confirmed

The equal classes are the important addition. Without them a pivot a whisker above the last one counts as a higher high and confirms a trend that structurally is not there. A marginal new high is a range, not an advance, and the engine now says so.

StateConditionColour
UptrendA higher high after a higher low, or the reverse orderGreen
DowntrendA lower high after a lower low, or the reverse orderRed
SidewaysEither equal class, a broadening pair, or anything mixedAmber

03Pivots, and the state it keeps

Pivots are strict extremes over a symmetric window, so a pivot is confirmed only after its right-hand bars have printed. The window length resolves from the chart's own timeframe.

ChartLength
Monthly1
Weekly5
Daily2
Intraday2

Left and right use the same value — symmetric detection. These four numbers are canonical across the system; other engines that detect pivots are expected to use them.

The persistent state, and why each piece exists
StateWhat it holds
Locked high / lowThe most recent confirmed pivot of each type
Previous locked high / lowSaved just before the lock is overwritten. Used as the structural reference when an active pivot extends — without it, an extending pivot compares against itself
Active pivot — price, type, barThe latest extreme in the current direction. Equal to the locked value at confirmation, then drifts as the pivot extends
Last high class / low classThe classification of the most recent confirmed pivot on each side. Section 05 reuses these rather than reclassifying

04The state machine

Called on every confirmed direction change. It returns the new trend and the new swing count.

New pivotPrior opposite classTrend
Higher highHigher lowUptrend

Lower lowLower highDowntrend

Higher high after a lower lowBroadeningSideways
Lower low after a higher highBroadeningSideways
The counting rule

Consecutive sideways pivots count. The swing count resets only when the trend state changes — an earlier version zeroed it on every sideways pivot, which made a long range look permanently young.

05The developing pivot — the part that makes it usable live

A confirmed pivot label arrives late by construction: it cannot print until its right-hand bars exist. If the panel only ever read confirmed pivots, it would be describing the past. So a third section watches the leg in progress and classifies what the next confirmed pivot would be.

SituationReads asAnd if the confirmed opposite class agrees
Active low, the developing high exceeds the locked highA developing higher highBullish break of structure — the trend flips up now, not in two bars
Active high, the developing low breaks the locked lowA developing lower lowBearish break
Anything broadening or mixedSideways—

Trend, structure, swing count, swing range and choppiness all read the developing value where one exists, falling back to confirmed otherwise. That is why the panel can be trusted mid-leg while the chart labels still lag.

Two fixes that made this section reliable — and the repaint trade-off
  • It gates by which side is active. Previously both sides were evaluated even when only one was structurally relevant, producing false flips on an extending pivot.
  • It reuses the confirmed classification rather than reclassifying from the projected extreme, which removed a source of micro-drift.
  • The sync window includes the pivot bar itself. Without that the engine missed the pivot bar's own extreme — it started counting a bar late.

By default this section is live, which means it repaints intrabar. A developing break can appear and disappear inside a bar. That is deliberate — it is what makes the panel current — but it makes a naive alert noisy.

The confirmed-bar projection input restricts these writes to closed bars. Off gives you the live read; on gives you a calm panel and a non-repainting alert path. Set break alerts to fire once per bar close regardless.

06Major and minor pivots

A pivot is major when its move from the opposite locked level exceeds a threshold — 8% for stocks, 4% for funds, detected automatically, or a value you set. Major pivots draw with a thick line and a full-size label; minor ones stay thin and small.

This is not decoration. It is what lets you read a chart's skeleton at a glance and ignore the noise pivots that a two-bar window necessarily produces.

Do not override a fund to the stock threshold — you will lose most of its structural pivots, because a 4% instrument rarely moves 8% between pivots.

09The workflow, longs only

  1. Regime. Confirm the timeframe, read the trend, check both higher timeframes. Aligned is a green light; conflict is a reason to stop reading.
  2. Structure. What pair governs right now, how mature is the run, has the move covered meaningful ground.
  3. Quality. Is this instrument trustworthy at all — choppiness — and is the current swing fresh or aged.
  4. Levels. Take the break level as the trigger and the invalidation as the stop. Reward against risk is the first extension minus the break level, over the break level minus the invalidation.
  5. Volume gate. Was the most recent upward break on confirming volume? If not, wait for one that is, or take reduced size.
  6. Cross-check. The dashboard's strict-trend field reads this same logic, so the two should agree. If they do not, that is a bug worth chasing — not a judgement call.
Longs-only mode changes what two rows mean

With it on — the default — invalidation tracks the swing low, the break level tracks the swing high, and only bullish breaks are captured. Turn it off and invalidation reverts to the active pivot, which is a different quantity that reads the same. If a downward arrow ever appears in the volume row, the toggle is off.

11Mistakes to avoid

MistakeWhy it costs you
Chasing a pivot labelLabels print late by construction. The pivot already happened — read the developing fields on the panel instead of waiting for the text
Trading the amber stateSideways means no structural consensus. Wait for resolution, or trade the edges knowing that is what you are doing
Ignoring the higher-timeframe rowsCurrent up against higher-timeframe down is a counter-trend bounce, whatever the panel's own trend cell says
Acting on a stale volume confirmationThat field is sticky — it holds the last break's reading. Many bars later it is history, not a signal
Mismatching pivot lengths across modulesTwo tools with different windows produce different trend labels on the same chart, and you will spend the afternoon reconciling them

12Who consumes this engine — and the drift it caused

Every strict-trend read in the system traces back here.

Both screenersPorted to gate the trend requirement

What that dependency actually cost

The Python port of this engine was three versions stale, and both screeners carried their own byte-identical copy of it. Seven divergences from the current Pine had accumulated, including the equal-pivot threshold being twice as tight, the equal classes wrongly confirming a trend instead of forcing sideways, and — the same bootstrap asymmetry from section 01, never ported.

Because the stage read at the time carried two unconditional overrides keyed on this trend, every strict-trend error became a wrong stage digit, and an over-eager uptrend rescued a genuine decline into a base. Eleven of thirty-eight board names disagreed with the chart.

How it was resolved — both halves

The duplicate copies collapsed into one shared module — strict_trend.py, with all seven fixes and a regression suite. Separately, the two stage overrides were removed entirely — a stage that a different engine can silently rewrite is a stage you cannot reason about.

So this engine no longer feeds the stage read at all. It defines structure; the stage engine defines stage. That separation is the point.

Five of the seven fixes have a test that fails without them

Each of the five was mutation-verified: revert the fix, and a test goes red. Two were not. The extension re-classification and the window-boundary offset need an extension event and a boundary case that the real-data fixtures happen not to contain, so nothing would catch a regression in either.

That is stated here rather than smoothed over, because a suite whose coverage you believe to be uniform is more dangerous than one you know the holes in. If either of those two behaviours ever needs changing, the test to trust does not exist yet — write the fixture first.

Standing rule

Keep the pivot lengths identical everywhere. They are the one input that, changed in one place, makes two correct engines disagree — and the disagreement looks like a bug in whichever tool you check second.
