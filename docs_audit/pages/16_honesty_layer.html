The Honesty Layer

Every claim about a strategy's edge is produced here. The framework replays the screeners at historical dates, grades the picks against their matched-horizon forward returns, and tells you whether an edge is real, in which regime, and whether it survives out-of-sample.

01Core concepts — read these first

Matched alpha, the metric that matters

Alpha = your return − the benchmark's return over the same window. It answers the only question worth asking: did this beat the market, or just ride it? A +8% trade in a +8% market is zero alpha — single-stock risk taken for nothing.

“Matched” means each trade is measured over its own design horizon, not a fixed 30 days:

CatalystMatched window
POS-ACCUM180 d
POS-BO · WYC-*120 d
REV-* recovery90 d
SWG-PB60 d
SWG-BO · GAP30 d
The cardinal rule

Never judge a positional or recovery setup on a 30-day window. Measuring a 120–180-day setup over 30 days is invalid — it produced false “remove this catalyst” calls in May 2026 that all had to be rolled back. Always pass --catalyst_windows.

Up tape / down tape — the regime cut

The direction the benchmark moved over the trade's forward window. Splitting alpha by tape is the regime test.

Corrected since this guide was written

This section originally concluded that recovery and breakout setups are defensive — positive in down tapes, lagging in up tapes. That result was an artifact and is retired. It came from benchmarking a trade's full design window against a stock leg that had usually exited far earlier; an 8-day stop-out at −3% measured against a 120-day index at −10% books seven points of alpha that were never earned.

Worse, after the fix the direction label became endogenous: the window's length is now days_held, which is an outcome. Fast stop-outs self-select into “down”, long runners into “up”. Do not quote any per-direction result until direction is derived from an ex-ante window. The partition by family and by exit reason is unaffected and remains the decisive lens.

Win rate and profit factor

Win % is the share of profitable trades; PF is gross profit ÷ gross loss. Read them alongside alpha: a low win rate with big winners is a trend-following profile and still makes money; a high win rate with a few large losses does not.

02validation.py — the walk-forward harness

Runs the screener at each of N monthly anchors and aggregates per-anchor and overall.

python validation.py --months 24 --universe nifty500 --screener bull \
                     --catalyst_windows --bootstrap_n 10000 [--top_n 10]
FlagMeaning
--monthsNumber of monthly anchors
--universenifty100 / nifty500 — current constituents, so mild survivorship bias
--screenerbull or recovery
--catalyst_windowsPer-catalyst matched forward windows — use this
--bootstrap_nBootstrap CI on mean anchor alpha, e.g. 10000
--top_nKeep only the top N by score per anchor — mirrors the live Top-N, so this is the tradeable edge
--sector_rotationOpt-in RRG overlay. Off by default; strict cut alpha in testing

Outputs validation_runs/validation_<id>_{summary,details}.csv and updates LAST_RUN.txt.

On speed

The recovery screener fetches fundamentals at every anchor, so a 24-month recovery run takes 2–3 hours. Bull runs are far faster. The download timeout prevents hangs but does not change the base cost — run recovery detached and read the log later.

03replay.py — the execution simulator

For one anchor: pins data to that date, runs the screener, then simulates each trade bar by bar with stop, T1, T2 and Chandelier trail, charging 0.10% per leg in commission and slippage. Reports Sharpe, Sortino and Calmar.

Read the exit flags correctly — this distinction was once missed

Hit_Initial_SL is a true loss — use it as the failure metric. Hit_Trail_SL is often a profit-protect exit and must not be read as a failure. Conflating the two once produced a false panic that the stop was too tight.

The other half — replaying the live GO gate

The same file replays the four-gate GO against historical bars, so the entry the board and Section Four would actually have produced can be measured rather than assumed. Three switches decide what it models, and each has a default that is a claim about the live system:

SwitchDefaultWhat it asserts
LOCATION_RULEa2A pattern zone stands alone; a pivot shelf needs a confirming source. Set any to reproduce a pre-26-Aug run
entry_moderetestA limit at the trigger bar's close, not a buy-stop above its high — measured, and it beat the buy-stop across every family
STRUCTURAL_SLFalseThe structure-anchored stop is available and not used: it had the best mean and passed the OOS gate, and was still rejected because the median went from −0.48R to −1.01R and stop-outs from 11.8% to 52.7%
The defect this exposed, and the general lesson

Until 26 August replay ran the legacy location rule while the live surfaces had moved to A2. Every GO-gate run since 11 August therefore measured a gate the system was no longer using — and nothing about the output looked wrong, because a simulator that models the wrong rule faithfully still produces clean numbers.

The general form is worth more than the instance: when a harness and a live surface encode the same rule twice, they will drift, and the drift is invisible from the results. The only defence is to make the default track production and to say so where the default is written — which is why the table above states what each one asserts rather than only what it is set to.

And the rule itself measured as a null

Measured with those switches: the location rule is a null. Any-zone, A2 and pattern-only landed within 0.21 percentage points on matched alpha across eighteen anchors, while the trade count fell 221 → 88 → 51. Tightening location buys fewer trades, not better ones.

04walkforward_oos.py — the overfit gate

Splits the anchors chronologically — earlier 60% in-sample, later 40% out-of-sample — treats each anchor's alpha as a period return, and issues one of three verdicts.

PASS

OOS Sharpe ≥ 60% of in-sample, and OOS alpha above zero.

STOP

OOS degraded more than 40%. Overfit — do not proceed to weight-fitting.

NO-EDGE

In-sample alpha was already ≤ 0. Nothing to overfit; fix the screener or the window first.

Always per family, never pooled

A pooled STOP or NO-EDGE is usually one weak catalyst dragging several positive ones. Pooling has produced a false conclusion three separate times in this repo.

05catalyst_regime_partition.py — where the edge lives

Partitions trades by catalyst family, direction and exit reason, on matched alpha. This is the decisive lens, and it has overturned more conclusions than any other tool here:

  • The bull NO-EDGE was a composition artifact — four of five catalysts were positive and one drag was sinking the pooled number.
  • Recovery is regime-fitted, not broken.
  • The recurring exit signature: most catalysts' losers are early stop-outs and the survivors are big winners — the stops, not the signals, are the drag.

06data_provider.py — pinnable data

  • set_pinned_date(as_of) makes every fetch return data as of that date. No lookahead — this is the backbone of an honest backtest.
  • On-disk cache, rate limiting, and an NSE-direct fallback.
  • Hard download timeout. No fetch can hang the process — a stalled download aborts and continues via fallback or cache. One stalled connection once froze a run for roughly fifteen hours.

07The recommended workflow

  1. Run the tradeable configuration: --months 24 --universe nifty500 --screener bull --catalyst_windows --top_n 10.
  2. Partition it. Read per family and by exit reason. Identify the edge-carriers and the drags.
  3. Run the overfit gate — per family — before any weight-fitting.
  4. Never act on a pooled verdict, a non-matched window, or an in-sample-only number.
