01Attribution — decomposing realised P&L

Breaks closed-trade realised P&L across twelve dimensions, reporting n, win rate, total, expectancy, profit factor and signed contribution for every bucket.

The bookProvenance · System · Sector · Trade type · Hold period · Exit reason · Trade quality
The signal at entrySetup / catalyst · Entry stage · Alpha band · RS band · Conviction band
The honesty layer — the anti-NaN rule

Rows with a missing or zero exit price or quantity are quarantined and reported, never zero-filled. Cash-park instruments are excluded — that is risk-off carry, not alpha. Canonical P&L is byte-identical to the mentor engine's (exit − buy) × qty, and derived metrics are computed on read, never stored.

contribution_pct is the signed share of gross |P&L|, which stays robust on a net-negative book where a net-share would invert. Signal dimensions read “Unspecified” for trades closed before snapshots existed — a shrinking coverage gap, reported rather than imputed.

Provenance — the dimension that answers section 04's caveat

Provenance is the first cut, before sector or setup, and it asks one question: did this system choose this trade? A row counts as SYSTEM only when it carries a true entry snapshot — snapshot_meta containing |recompute, which only the guided-execution hook writes at the moment of entry. Everything else is DISCRETIONARY.

The looser rule — “any non-empty setup label counts” — was tried and rejected. A backfilled position re-screens as of today, so a name that happens to trigger now would be credited to the system retroactively. That is the same flattering-the-book error the exit reconcile exposed, in a new place. The strict rule cost the live record a trade when it landed; that is what a strict rule is for.

So the report prints two headlines side by side — SYSTEM-only and all-attributable — with SYSTEM foregrounded. The mixed history is not separable, but it is no longer growing. Every GM guided-exec entry that closes from here lands on the correct side of the line, so the caveat in section 04 has a clock on it rather than being permanent.

02The lean entry snapshot

Adds six curated columns to the journal so attribution can slice by signal — setup, entry_stage, entry_alpha, entry_rs, entry_conviction, snapshot_meta. Values come from the zero-drift price-action mirror, so no TradingView is needed.

ModeWhat it does
--mode migrateIdempotent schema migration
--mode backfillAs-of-today snapshot of OPEN trades, stamped backfill
--mode symbolOne trade
Auto-capture on new trades

A hook in upsert_trade() captures a true recompute snapshot on every new OPEN insert — after commit, and guarded so a fetch failure can never block the save.

A limitation by design, not a gap

setup is only meaningful at true entry, because the catalyst is live at trigger time. A backfilled open position re-screens today and shows setup=NONE when it is not currently triggering. Only trades entered because they triggered carry a real setup label.

03The daily journal ↔ broker sync

Keeps the journal's OPEN positions identical to the live book. It is allowed exactly three verbs:

ADD

Live holdings missing from the journal, plus one backfill snapshot.

UPDATE

Quantity and average price where they have drifted from the broker.

CLOSE

Journal OPENs no longer held — only with a completing sell in the trade history giving an authoritative exit price and date. Otherwise it flags, never forces.

The safety that matters most

The sync aborts entirely if the holdings fetch fails or returns an empty book. An API hiccup must never be read as “everything was sold”. Cash-park instruments are ignored on both sides, and --dry-run / --no-close are available.

Scheduled as a Windows task, weekdays at 16:30 IST post-close, with catch-up enabled so a machine that was off still runs it. Logs to logs/journal_sync.log.

04The exit reconcile

A one-time data recovery that pulled missing exit prices out of the broker's trade history. Two silent bugs were fixed in the process, and both are worth remembering as a class:

  1. The token call sat outside the try, so a stale token crashed the entire reconcile instead of degrading to local logs.
  2. The trade-history API returns only a security id and a full company name — no ticker. The old code reached for a column that never existed, threw, and had the error swallowed by a bare except. Resolved by resolving ids through the full NSE scrip master.

The finding that mattered

Missing exit data had been flattering the book by roughly ₹4.4 lakh. The painful exits were precisely the ones with no recorded price.

Corrected since this guide was written — read this before quoting the number

This guide calls the reconciled figure “the honest number all strategy work is measured against”. That framing is wrong and has been retracted. The loss is substantially tax-loss harvesting — 21 of roughly 25 harvest exits were a single financial-year-end batch — and those names were discretionary picks that never came from this system (ETFs and large-cap defensives).

The journal mixes system-entered and hand-picked trades and cannot be separated retroactively, so no clean live track record of the system exists yet. The reconcile is still correct as an accounting exercise — the book really did lose that money — but it is not a verdict on the strategy. Build the system-only record forward from trades carrying a true recompute entry snapshot.

05Key reminders

  • Trade off the live broker book, not the journal alone. The daily sync makes them match, but the broker is authoritative — before the sync existed the journal held a stale closed position and wrong quantities.
  • No Stage 3/4 holds. The entry snapshot surfaces violations; act on them.
  • Backups are taken before every reconcile or sync write. The database is data and is not git-tracked — it is preserved through those dated backups, so do not rely on version control to recover it.
