What still works without a broker token

Every screener and analysis page. They run on market data, not the broker. Only the portfolio vitals, GTT view and order surfaces need the token — so an expired token costs you execution, never research.

Two button styles, and the difference matters

Launcher buttons fire a backend script in a separate console. The page does not block and will not tell you when it finished — watch the spawned console, then come back and refresh. Inline actions run inside the page with a progress bar.

Two pages that are not where you would look for them

There is no PYRAMID page. The add / trim / reduce ladder is computed inside RISK SHIELD, which is the right place for it — an add is a decision about a position you already hold, and it has to be read next to that position's stop, not on a screen of its own.

GOLDEN MATCHER sits under Execution, not Discovery, and the distinction is the whole architecture: the watchlists qualify, the board times. By the time a name reaches the board it has already been chosen. What is left is when.

Two buttons on the Golden Matcher that produce text, not orders

The board builds a one-paste bundle — everything the chart cannot compute for itself: what qualified each name, its fundamental verdicts, its board rank. A second button builds an options bundle — put-call ratio, max pain and the writer strikes, for the F&O names only. Both are pasted into the chart indicator, into two separate fields; putting one in the other's field wipes it. The options bundle is a button rather than part of the rebuild because it costs one broker call per name at one call every three seconds.

The sidebar's one-click button

Run Auto-Pilot fires the whole daily pipeline — scanners, fundamentals, matcher, watchlist sync. It runs in a separate console and takes several minutes. This is the button that makes tomorrow's shortlist.

03The reading order

State of Market → Pre-market → Dashboard → Discovery → Execution. Never trade against the tape.

Analysis pages are for evenings and weekends, not for the middle of a session. The order exists because each stage can end the day's hunting: a risk-off tape means bull breakouts are low-probability regardless of what any individual chart looks like.

04The decision stack

The same DNA surfaces everywhere: Stage → RS → volatility → alpha → risk. Read in that order, top down.

  1. Tape. Is the regime risk-on? Is breadth improving? If risk-off, only recovery setups earn a look.
  2. Sector. Prefer sectors that are leading. Skip a stock in a lagging sector regardless of its own chart. Note what was measured: of the rotation transitions, only leading → leading and weakening → leading were positive in both windows; improving → leading was reliably negative.
  3. Catalyst. Match the catalyst to your intended style — the map is below, and the catalyst is the horizon.
  4. Quality. The fundamental scorecards confirm the backbone; the recovery gate is a hard floor, not a preference.
  5. Location and trigger. Price at a fresh demand zone, then a closed trigger bar. Never buy at the zone on the touch — this is the single most expensive habit the whole system is built to prevent.
  6. Risk. Size off ATR so risk is a fixed share of capital, and place the protective order the same evening.

The catalyst decides the horizon. It is not a preference you apply afterwards.

The lesson baked into the system

The signals find edge; tight stops on long holds give it back. Match stop width to the catalyst's horizon, and judge results per family, never pooled.

07The Dashboard — your open book

No tabs; a single stacked read of what you actually hold.

  • Health vitals — unrealised P&L, return on deployed capital, current value, win rate, average gain and loss, reward-to-risk.
  • Exit signal scan — checks stop proximity, R-multiple, stage decay and fading relative strength across open positions, and separates the ones needing action from the healthy. Regime-aware.
  • Closed-trade performance — Sharpe, Sortino, max drawdown, profit factor, expectancy.
  • Active positions — with a stop-status column that reads locked when the stop sits above entry, breached when it doesn't, and the distance otherwise.
  • Correlation risk — the diversification score and any shadow-concentration pairs.
The tile worth acting on

Shadow concentration is the one most people ignore. Two positions that look like diversification while moving together mean your real exposure is roughly one position of double the size — and you will only discover that on the day it matters.

A launcher that spawns a dead script tells you nothing

These buttons fire scripts in separate consoles. If one has crashed at launch — a missing dependency, an expired token — the page still shows a successful click. When an agent seems to have stopped working, check its log rather than the button. The trail ran dead for six weeks this way, twice: once on a missing dependency, once because the daemon it was scheduled inside restarts with the app and had fired exactly once. Since 9 September the trail is a Windows Task Scheduler job (GTT_Trail_Daily, 15:45), outside the app entirely, with a pre-flight lint that Telegrams a code fault instead of leaving a job that looks like it ran.

08bRisk Shield — the three tabs

One page, three jobs, in the order you use them across a day. All three read the same brain: risk_common for the Chandelier and trade type, pyramid_logic for the ladder, and the live broker book for what is actually resting.

TabWhat it is for
✅ Morning Approval DashboardAdded 9 September. The trail engine's proposals — one row per resting order ID, not per symbol, because eleven of fifteen names carry two OCOs and both stop legs need moving. Each row shows the current stop, the proposed Chandelier, the tighten in %, the trade type and the size action from the ladder. You can edit a proposed stop, tick the rows you approve, and press Execute Approved SL Updates on Dhan. The button enforces tighten-only; a row whose Chandelier sits above the LTP is shown as BREACHED and never pushed; trail-only cells stay blank on rows that have nothing to trail. The same engine runs unattended at 15:45 — this tab is for the days you want eyes on the batch first
🎯 Active Exits (OCO)One tile per position: what is at Dhan now on the left, the recommended levels on the right (policy R off the entry-fixed risk unit, tighten-only stop), the SL's ATR multiple from entry, the Chandelier gap from the LTP, and a timeline with the trail marker. Legs off the R-canon are flagged ⚠ vs 2.0R. The AI review on each tile is prompted with the ladder's verdict, so it reconciles with the Pyramid tab instead of contradicting it
⚖️ Pyramid / TrimThe five-rung ladder — EXIT → TRIM → REDUCE → ADD → HOLD, priority order, best-of-each across the three engines. An ADD row carries the raised stop it implies (RAISE stop → ₹X) and never a lower one. The trade type is the ladder: journal Timeframe → setup prefix → stop distance in ATR → chart, first rung that can answer wins, and the badge prints which rung did
💰 Capital QueueOne queue for the next rupee: today's ADD-rated holdings and every live board name (5/5 GO or Buy Trigger Live, all three tabs) on one scale. Ranked by the Reviewer's context ladder — tier A = Stage 2 + leadership + a zone, B = Stage 2 + one of leadership / a level, C = the rest — then a concentration penalty (weight already in the name, sector above 20% after the order, correlation above 0.6 to any holding), then the board's Overall. Stage 3/4 and anything the order gate's sector cap would refuse are listed as blocked. Sized at the house risk and the ₹1,00,000 per-trade cap (house_policy.py), then walked down against your Dhan cash. EXIT / REDUCE / TRIM proceeds count only when you tick Count EXIT / REDUCE / TRIM proceeds as available — off by default since 25 Sep, because in a recovery tape you are holding, not exiting, and a queue that spends exit proceeds spends money that does not exist. The ADD/TRIM/EXIT classes are the live ladder when Risk Shield has computed them this session, else the 16:30 snapshot; the Book metric says which. Organising tool, not a measured edge: adds and new entries measured indistinguishable in R (PREREG_add_premise, 25 Sep), so the choice is made on risk — an add concentrates, a new name diversifies.
⚙️ Settings & OverridesManual SL mode — Floor (default: the Chandelier can only be tightened to your hand-set stop) or Exact (your stop is used verbatim). Saved since 25 Sep, so the 15:45 GTT trailer and the Morning Approval proposals apply the same mode; before, the mode lived in the browser session and the trailer always applied Floor. The old "Risk budget % per trade" input is gone: the Portfolio Heat card now budgets each open position at the house rule (stock 0.5% · ETF 0.75%, house_policy.py) of the declared capital — it was a session-only 0.25% labelled "execution freeze"
25 Sep — one rule, many screens

An integration audit found the same rule held in several places and drifted apart: five sizers on four risk rates, a ₹50,00,000 capital invented when Dhan was down, four copies of the bear threshold (one of which read a regime score of 0 as not bear), COMMAND's E-02 trailing stop computed a fifth way, and Risk Shield reading earnings from a different source than the pyramid ladder. Each now reads one owner — house_policy.py for risk, capital, caps and the bear rule; risk_common for the Chandelier; the nightly earnings_calendar cache for dates. Details in AUDIT_LEDGER.md, AUD-INT-01…12.

Two things fixed on 10 September, both worth knowing the shape of

Pressing RISK SHIELD opened the Journal underneath it. One line imported the journal module for a filename, and that module is a whole Streamlit app that paints on import. Golden Matcher had been importing it earlier by accident, which is why only Risk Shield wore it. Fixed by reading the constant without executing the module, and guarded by a test that flags any page-level import of a module that paints — a comment had already warned about this once and three call sites imported it anyway.

Tile text was unreadable. Border tokens (--bull-rule) had been used as text colour across the app — 3.5:1 on the green tiles, worse elsewhere — and one case hid behind a variable so a literal search missed it. A contrast sweep now resolves every text colour against the background declared in the same string literal; grounds are surface*, text is ink*/muted, and -rule is only ever a border.

09Workflows

Swing — 8 to 12 weeks

  1. Tape check. Proceed only if risk-on or neutral.
  2. Fresh lists from the auto-pilot.
  3. Screen for the swing catalysts and sort by score.
  4. Sector gate — drop anything whose sector is lagging; prefer leading.
  5. Quality on the top few names only.
  6. Location and trigger on the real chart. Wait for the closed bar.
  7. Size and protect — enter off S4's Plan row (a retest limit at the trigger close by default; never a limit resting at the zone before a trigger). Protective order the same evening.
  8. Manage via the exit scan and trailing engine. Trail under structure; take partials into the target band.

Positional — 6 to 8 months

  1. Regime and sector — you want breadth improving and a sector in early leadership.
  2. Hunt the core edge — the positional catalysts, on the broad universe, ranked by alpha.
  3. Stage confirm on the weekly chart. A clean Stage 2, not a hopeful one.
  4. Fundamental backbone — reject weak balance sheets outright.
  5. Entry on the breakout or the first pullback, with a wide stop so ordinary volatility cannot shake you out.
  6. Size respecting that wide stop — which means a smaller share count, not a bigger risk.
  7. Hold. Review weekly. Exit on stage confirmation or the trail — not on noise.
  8. Rotate when a position decays, freeing that capital into the highest-conviction candidate.

End of day and weekend

EOD: post-market → dashboard vitals → confirm protective orders are live → set tomorrow's alerts. Weekend: autopsy what worked by catalyst and sector → check whether the edge is holding → refresh the watchlists.

10Every page, in detail

Folded by group. This is the reference for what is on this page and what each field means — the thing you open when a tab is unfamiliar or a number is unexpected.

🩺 State of Market — Macro · Breadth · News

Macro Radar

  • Overview — a tile per instrument with its one-month change, a risk-on/risk-off read of the complex, and a 12-month trend rebased to 100 so every series is comparable on one axis.
  • Global Indices — the full world board with change and 52-week range.
  • FII/DII Flows — cumulative foreign against domestic flow over time.
  • Sector RRG — rotation of the sector indices against the broad index. Leading, improving, weakening, lagging. This is the sector filter you apply before drilling to stocks. The rotation maths is locked and read-only.

Breadth Engine

  • Regime — a single composite from breadth, advance/decline, McClellan and percentage-above-averages. This is your master gate: it decides whether bull setups or recovery setups are in season.
  • Overview — percentage above the 50, 150 and 200-day averages (the 200 is the big one), share of the universe in Stage 2, new highs against new lows, advance/decline and high/low ratios.
  • Sectors — each sector's stage tally, over a selectable lookback.
  • McClellan — oscillator, summation index, a text verdict and the thrust reading. It warns when the data is more than a week stale, which matters because a stale breadth read looks exactly like a calm one.
  • Stage Map — the full stage distribution across the universe.

News

Headline counts split bullish / bearish / neutral with a net sentiment label. Three tabs: the free feeds, your paid analyst recommendations (with a cookie-freshness indicator, because an expired cookie fails quietly), and a per-symbol filter.

📅 Daily Intel — Pre-market · Dashboard · Post-market

Pre-market hub

  • Brief — the canonical full briefing. The dashboard shows only a snippet of this one.
  • Global — the overnight pulse across equities, commodities, currencies and bonds.
  • Calendar — economic and corporate events.
  • Options — the pre-market snapshot: put-call ratios by open interest and volume, max pain, at-the-money volatility, and the call and put walls — the strongest open-interest strikes, which act as magnet and support. Same broker-sourced chain as the Options Desk, so it reads before the open rather than only during the session.
  • Paid feed — filtered to overnight and morning-brief headlines.

Dashboard — the open book

No tabs, a single stacked read. Health vitals across eight tiles; the exit signal scan checking stop proximity, R-multiple, stage decay and fading relative strength; closed-trade performance; a heatmap sized by capital and coloured by return; active positions with a stop-status column; and correlation risk with the diversification score and any shadow-concentration pairs.

Post-market

The end-of-day summary, provisional institutional flows with five-day sums, top movers across a selectable universe, and the paid feed filtered to closing-bell headlines.

🔍 Discovery — Hunter · Watchlist · X-Ray · ETF · Portfolio

Hunter — the screening workhorse, six tabs in workflow order

  1. Scans — launchers per strategy. Positional: stage-2 hunter and early accumulation. Swing: pullback and strong leaders. Recovery: the three post-shock variants — use these only when the market is well off its high.
  2. Fundamentals — fetch, then process. This produces the snapshot the matcher needs.
  3. Golden Matcher — combines the technical scans with fundamental conviction. Shows freshness and warns when the output is more than a day old. Below it, the meta-ranking concatenates all four files and ranks by conviction.
  4. Bull Screener — the Python port of the catalysts, pure price action. Pick a symbol source (the combined picks, the broad universe which is backtest-aligned, the futures basket, or an upload), then filter by catalyst and minimum score. Exports filtered CSV and a symbol array for the chart. Broad-universe runs are strict; an upload keeps tracker mode.
  5. Recovery Screener — hold-window aware, so it is safe to run post-market and at weekends. Filter by signal type, minimum relative strength and maximum signal age. The output carries the fundamental score, which is the hard gate.
  6. X-Ray batch — deep fundamentals across a list, filtered by overall rating and quality score, with a single-symbol quick look at the top.

Watchlist — eight tabs

Opens with the latest pipeline output and a pipeline health panel that lets you re-run a single broken phase rather than the whole thing. Then: local generation and a symbol-array generator; cloud sync and email dispatch; smart rank, which scores a symbol source over a chosen lookback; the sector database with coverage and a lookup; the data cache with its freshness and size; the pipeline phase report; replay, which asks what a screener would have picked on a past date and how those picks did; and the live track record of every pick logged.

X-Ray — single stock, six tabs

Snapshot (valuation, profitability, balance sheet), the income statement, quarterly results with a trend chart, the scorecard carrying both quality scores, a multi-stock fundamental screen, and news with corporate announcements and analyst consensus.

ETF — a parallel pipeline

Top picks, sector rotation on a composite relative strength, the asset-class regime detector with an allocation view, and liquidity scoring. Liquidity is the number-one ETF risk — a large share of listed ETFs trade too thin to exit cleanly.

Portfolio analytics

Overview and allocation; risk metrics — value at risk at a chosen confidence and lookback, conditional VaR, annualised volatility, max drawdown, and factor exposure against the index (beta, correlation, tracking error, alpha, Sharpe, Sortino); historical stress scenarios replayed against your actual book; and a walk-forward stage-2 backtest with a selectable rebalance and universe.

⚡ Execution — Command · Options · Sidecar

Command Center

Active Ops holds the live agents — order execution, the stop auto-shield that pushes journal-derived stops to the broker, mobile monitoring, the intraday scanner, and the webhook gateway that turns a chart alert into an order. Inline beside them: the exit scan, the trailing engine, and the rotation guard that grades every open position.

Ledger carries the live trade ledger and the sync that pushes it into the chart's portfolio slots. Price Alerts is add, pause, remove, check-now, and fired history.

Options Desk

The live chain with a spot, put-call ratio and max-pain snapshot, a strike-range slider driving open interest, change in open interest, volatility skew, and a near-the-money table. Plus external links and a concepts reference.

The chain comes from the broker, not the exchange. The exchange serves a chain only around market hours and its index endpoint returns a hard 404 — index chains had been failing permanently rather than intermittently. The broker answers after hours and is authenticated rather than cookie-scraped; the exchange stays as a fallback. The cost is a rate limit of one request every three seconds, which is why a multi-symbol build is slow by design and not stuck.

A field that could not be read now renders as a dash, never a zero. That distinction matters off this page more than on it: three of these numbers travel to the chart as drawn price levels, and a max pain of zero draws a confident line below every stop that looks exactly like a real one.

TV Sidecar

A quote strip, key technical levels — price against each major average with distance, the ten-day range, and ATR — and a multi-panel chart. A fast read-out to glance at while your real chart is elsewhere.

🔬 Analysis — Autopsy · Backtest · AI Lab

Autopsy — five tabs

  • Overview — trades, win rate, total realised, Sharpe, profit factor, expectancy, max drawdown, average win and loss, holding-period analysis and the equity curve.
  • Calendar — monthly profit and loss.
  • Sectors — sector breakdown and coverage, so you can see which sectors you have never traded at all.
  • Trade Quality — the quality distribution and your win and loss streaks.
  • Attribution — realised performance decomposed, with a data-quality line stating what was excluded, what was quarantined as incomplete, and how much of the sample carries an entry snapshot. Led by the entry-signal drivers — setup, stage, alpha, relative strength, conviction. Reads the journal directly, no network.

Backtest lab

Forward-return analysis of screener signals per holding horizon: win rate, average and median return, best and worst, a breakdown by edge type, the return distribution, and return against signal age — which is how you find out whether a stale signal is still worth taking.

AI Lab — four tabs

Pre-flight proposes a trade from a symbol, entry and risk, returning a grade, a score, a suggested stop and a quantity — then can place the entry and its protective order together. Generative covers stock analysis at selectable depth and a portfolio review. Workflows holds the pipeline launcher and a sizing interface that computes quantity, trade value, risk and targets before executing. Weekly report generates the week's summary.

📁 Records — the journal

Opens the trade journal inside Mission Control (ported in-app 23 Sep; the standalone app reads the same database) — active trades, closed history and the performance lab, with entry snapshots. It is kept in step with your broker book by the scheduled daily sync, so the journal you open is already reconciled rather than something you have to reconcile first.

A legacy fundamentals page still exists in the code but was absorbed into X-Ray and is no longer in the sidebar. A second copy of the journal also lives in pages/3_journal.py; it duplicates the standalone and is due for removal.

The modules underneath — and how to use this list

The app is a shell over roughly fifty-five modules in a few layers: data and infrastructure (the provider, caching, the sector database), broker, auth and execution, the screening engines that are the zero-drift core, the analysis and reporting modules, and the agents that run on a schedule.

Why this matters operationally: almost nothing on a page computes a signal — pages render what an engine produced. So when a number looks wrong, the question is which engine produced it, and the answer is in that engine's own guide. It also means a page can look healthy while the engine behind it has failed, which is exactly the launcher problem above.
