Process · GM + S4 ecosystem

The Operating Loop

The machine qualifies overnight, you arm in the evening, the alerts watch the session, and you only open a chart when one fires. Everything on this page is either automatic or one of two moments that need judgement.

The two-stage doctrine inside that

The GM fires early — a name is armed. S4 is the strict execution gate — a trade is triggered. They are deliberately not aligned. GM arms → you focus → you wait for the S4 GO. Collapsing them would destroy the thing that makes the shortlist useful.

Alongside it: Post-Market Summary, and the journal ↔ Dhan sync — which aborts rather than guess if the holdings fetch fails or comes back empty.

evening

Review and arm← you · ~15 min

The one step that needs judgement. Everything else today is a machine or a reaction to one.

  1. Restart clean. STOP_COMMANDER.bat → relaunch. A browser reload does not reload code.
  2. Rebuild the board — Fetch fresh data + rebuild (it rebuilds itself; don't also press Rebuild).
  3. Read the header before the rows. Failure counts, source-issue strip, provenance, AGE. An empty source list means part of the shortlist is silently missing.
  4. Work top-down. The board opens filtered to all-gates (4/4), sorted by Overall. Open Single Symbol on anything worth attention.
  5. ARM what you intend to stalk. The highest-value action of the evening — an armed name is injected into every later board union with the archetypes it had when armed, so it survives after it stops qualifying.
  6. Create tomorrow's alert on the new dated watchlist.
  7. Check the sector-mix strip. Over the cap means you are about to over-concentrate.

The session— do not watch the board

The board's auto-refresh is a browser timer: Chrome throttles it when the tab is hidden, and it stops entirely if Streamlit is down or the Dhan stream drops. It is not the layer to depend on intraday.

TradingView alerts fire on TV's servers — laptop shut, app crashed, feed down, the ping still arrives.

The second moment that needs judgement — and it is only as good as the arming was, because an armed name is one you have already thought about.

Every evening

The alert ritual

The auto-pilot writes a new, date-stamped TradingView watchlist each evening, so yesterday's alert points at yesterday's list by construction.

  1. Check the source-issue strip first. On a thin auto-pilot day you would otherwise arm a near-empty watchlist and lose a day of coverage silently.
  2. Delete yesterday's alert. Left running it fires on names that already dropped out, and eats the alert quota.
  3. Create today's — condition S4 GO (PA + Location + Volume + Bar), trigger Once Per Bar Close, app push on, named to match the watchlist: S4 GO · GM-20AUG · 75m.
  4. Repeat on a 125m chart. An alert inherits the chart's resolution, so each timeframe needs its own.
TimeframeBar closes
75m10:30 · 11:45 · 13:00 · 14:15 · 15:30
125m11:20 · 13:25 · 15:30

125m is not just "slower". Its first close is 11:20 — after the opening drive, whereas 75m's first close is the opening drive. It skips the noisiest bar of the session by construction, at the cost of two fewer ping windows.

Two pings, one setup

A name firing on both timeframes is one setup seen twice, not corroboration — same engine, same gates, only the sampling rate differs. They share the 15:30 close, so duplicates cluster there. Check the panel on the timeframe you intend to act on and treat the other as an echo.

Two things worth knowing

Recreating daily also refreshes the GM lists frozen into the alert at creation, so pullback context never goes stale. And every S4 recompile deletes all alerts — they bind to the compiled script id — so recreating after a compile is mandatory, not housekeeping.

On the ping

The execution path

ping  →  open S4 on the alert's timeframe
      →  read the SUMMARY (bottom-right column) first
      →  run the 12-step checklist, stop at the first NO
      →  size at 1% risk on the honest stop (≥ 1×ATR)
      →  place entry + GTT stop
      →  log the decision, including a pass

Read the SUMMARY before the rows. It is the only field that weighs one section against another, and its last line tells you which case you are in:

The SUMMARY saysMeaning
This is a take-itTrend, leadership, location and geometry agree. Execute the plan as written.
Setup sound,
plan is not		The most common case. Fix the entry, the stop or the target — do not take the plan as printed.
Context against itCounter-trend. Legitimate only if you size it as one and take the first obstacle as the target.
The two prices you must know before entering

SL is where you get out. INVAL is where the reason you bought stops being true. If they are the same price, you have no room to be wrong — wait for a deeper entry.

88% of positional exits come from the trail, and only 8.4% ever reach 3R. Targets are upside; the trail is the mechanism. Do not tighten it — four studies have rejected that.

Everything above the line is machinery. The two moments that need judgement are arming in the evening and the checklist at the trigger — and the second is only as good as the first.

Process, not ceremony. If a step stops earning its place, remove it — but remove it deliberately, and write down why.
